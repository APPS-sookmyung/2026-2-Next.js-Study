## Page Router란?

- 많은 기업에서 사용되고 있는 안정적인 라우터
- React Router처럼 페이지 라우팅 기능을 제공함
- /Pages 폴더의 구조를 기반으로 페이지를 라우팅
    - 밑에 자바스크립트 파일을 저장해 두면 자동으로 파일 이름과 경로에 따라 라우팅됨
    - ~/ → index.js
    - ~/파일명 → 파일명.js로 접속됨
    - ~/폴더명 → 폴더명 밑 index.js
        - 동적 경로도 가능 ~/폴더명/1 2 3… → [파일명].js 으로 하나씩 매핑됨
        - […파일명].js → 여러 개의 id가 연달아 들어올 수 있음 : catch all segment
        - 폴더명 뒤에 아무것도 오지 않는 경우 → index.tsx 추가하거나 [[…파일명]].js : optional catch all segment

- 실행 npm run dev
- 실행종료 ctrl + c / ctrl + d
- /public : 페이지 내에서 사용할 이미지 파일들
- /src/pages  : 페이지의 역할을 할 컴포넌트를 보관하는 파일들
- /src/styles : 컴포넌트/앱의 전체적인 스타일링을 담당하는 css 파일들
- _app.tsx, _document.tsx : 페이지X, 모든 페이지에 공통적으로 적용되는 로직, 레이아웃, 데이터를 다루기 위해 필요한 파일들
- react에서의 app 컴포넌트 - 모든 컴포넌트들의 부모 컴포넌트 역할, 루트 컴포넌트로써 존재
- next에서의 app 컴포넌트 - 모든 페이지 역할을 하는 컴포넌트들의 부모 컴포넌트 역할

```jsx
import "@/styles/globals.css";
import type { AppProps } from "next/app";

export default function App({ Component, pageProps }: AppProps) {
  return <Component {...pageProps} />;
}

export default function App({ Component, pageProps }: AppProps) {}
-> Component : 현재 페이지 역할을 할 컴포넌트
-> pageProps : component에 전달될 페이지들의 props를 모두 객체로 보관해둠

```

→ 어떤 페이지를 렌더링하던 간에 app 컴포넌트 밑에 page 역할을 하는 컴포넌트가 렌더링됨

### document 컴포넌트

모든 페이지에 공통적으로 적용되는 html 코드를 설정하는 컴포넌트 

= 기존 react의 index.html 컴포넌트와 유사

- next.config.mjs : next 앱의 설정을 관리

### 네비게이팅

programmatic한 페이지 이동 : 링크 클릭 이동 X , 특정 버튼을 클릭했을 때 이동하는 것

### 프리페칭

현재 사용자가 보고있는 페이지에서 이동할 가능성이 있는 모든 페이지를 미리 불러옴

→ 빠른 페이지 이동을 위해 제공

항상 모든 페이지의 번들 파일 전달 X (용량이 너무 커져 하이드레이션이 늦어진다!) → 현재 페이지에 필요한 번들 파일만 전달하기 때문에 필요
